question: "How do people who use a workspace only for decisions and work, people who build apps with agents, and infra teams who run the factory over an estate each get a workspace that asks only what they need, and where do they start one from?"
options:
  - id: "a"
    label: "factory fields stay optional blocks, and three profiles in the reference workspace that chant workspace init --profile copies"
    how: "Nothing new is required of a declaration: the box block's factory and listing (ws-077), builder tiers (ws-094) and the app kind (ws-093) are each read and checked only when present, and plantable is a fact, not a finding. The reference workspace ships reference-workspace/profiles/ideation (the decision, work and answer kinds and a stub app of the app kind, no box and no factory), profiles/app (the same records and an app member whose box block runs it as a service and declares the factory over it) and profiles/infra (the same records and an estate member, a chant project on the terraform lexicon, whose box block declares only the factory, checked by a lint and a build, with no app member and no box services). Each is a template directory carrying copies of the reference workspace's kinds, so a copy reads on its own. chant workspace init --profile <name> runs chant init --from on reference-workspace/profiles/<name> of the chant repository at the reading chant's release tag, or of the repository or checkout --from names, so the copy has a lineage lock and can be upgraded."
    tradeoff: "One copy of each profile, in the place chant already tests against the commit under test, and init needs no new mechanism. The default source is the network: init fetches the chant repository at the release tag, so offline use needs --from with a checkout. Each profile carries its own copies of the record kinds, which a test keeps equal to the reference workspace's."
  - id: "b"
    label: "an opt-in level between records and signing"
    how: "The levels of #2525 gain a factory level, and the factory fields are refused below it."
    tradeoff: "The opt-in is named. A level is a ladder, and an infra team wants the factory without the app concepts a level would bundle with it; optional blocks already cost nothing to a workspace that leaves them out."
  - id: "c"
    label: "profiles generated by chant workspace init from code"
    how: "init writes each profile's declaration and files from templates inside @intentius/chant."
    tradeoff: "Works offline. The profiles would live in core, away from the reference workspace the issue asks to ship them, with a second copy of every record kind in the package and no lineage lock to upgrade them by."
choice:
  option: "a"
  reason: "#3146 already made every factory field optional and validated only when present, and ws-077 made plantable a fact rather than a finding, so the opt-in rule holds without a new level. What was missing is a place to start for each kind of user, and the reference workspace is where chant keeps the shapes it tests at every commit. Copying through chant init --from gives each new workspace a lineage lock, so a profile improves for those who started from it. The infra profile declares the factory with no app member and no box services, which is the case the ops update to the issue asks check to accept."
rejected:
  - option: "b"
    why: "A level bundles what an infra team wants apart, and the optional blocks already cost nothing when left out."
  - option: "c"
    why: "It moves the profiles out of the reference workspace and leaves the copies without a lineage."
