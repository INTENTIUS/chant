chant is a compiler. You declare infrastructure as TypeScript objects, chant checks them against a lexicon's lint rules, and it emits the target format, such as CloudFormation or GitLab CI. The build makes no API calls and keeps no state. Deploy and drift steps are separate, and you pick them per environment ([Lifecycle Models](/chant/concepts/lifecycle-models/)).

A chant workspace can also hold the infrastructure you already run. Terraform and OpenTofu roots, Pulumi programs and CDK apps join it as members. Each keeps its own tool, and chant reads it into the same graph and change set. The member kinds are listed in [Workspace kinds](/chant/reference/workspace-kinds/).

## With Terraform and OpenTofu

The [terraform lexicon](/chant/lexicons/terraform/) reads a root module's `.tf` files as they are. It lints them, adds the root to the workspace graph, and plans and applies it through the binary you name. `terraform apply` keeps working on your roots as before.

That binary can be `terraform`, `tofu` or `choudoufu`. [choudoufu](https://intentius.io/choudoufu/) is an OpenTofu fork that keeps each resource's ownership as a marker on the resource itself, two tags on AWS. Its plan reads ownership back from the live resources, so the state file becomes a cache. A root runs this way once it declares an estate ([choudoufu in Ops](/chant/lexicons/terraform/ops/#choudoufu)). choudoufu also runs on its own, with no chant workspace.

## With Pulumi

The [pulumi lexicon](/chant/lexicons/pulumi/) adds a Pulumi program to the workspace as it is. chant reads its graph from the checked-in stack export, its change set from `pulumi preview --json` and its drift from `pulumi refresh --preview-only --json`. chant runs only commands that change nothing, and `pulumi up` still applies the program.

[plunge](https://intentius.io/plunge/) is a Pulumi fork that runs the same programs, SDKs and providers with chant's ownership markers on each resource and one record per resource in its state backend. A member on plunge has the same kind and graph, and chant runs `plunge` where it would run `pulumi` ([A member on plunge](/chant/lexicons/pulumi/plunge/)). plunge also runs on its own.

## With CDK and CloudFormation

The [AWS lexicon](/chant/lexicons/aws/) emits CloudFormation templates, so its output deploys with the CloudFormation tooling you already use. A CDK app joins a workspace as a `cdk` member. chant reads the templates in its cloud assembly (`cdk.out`) and does not run the app. [`chant carve advise`](/chant/cli/carve/) reads the same assembly when you want to move a construct to a chant-built template.

## Owning less

The build path makes no API calls, holds no state and emits each platform's own format. At plan time it needs no provider SDK or state backend, and no credentials or network. Turning source into output takes a type-checker, an evaluator over a [static subset of TypeScript](/chant/concepts/typescript-as-data/), and the lexicon packages for the formats you target.

Fewer packages run during synthesis, and none of them reach the network or your cloud credentials. That leaves a smaller surface to audit. It follows from synthesis having no side effects. [Where Values Come From](/chant/concepts/where-values-come-from/) describes the same boundary value by value.

This covers the build path only. The apply side, such as a CI pipeline or [an Op](/chant/concepts/durable-workflows/), carries its own dependencies.

The output is the platform's own format, so it keeps working if you stop using chant.

## Pipeline engines

A pipeline engine decides where the pipeline itself runs. chant answers at build time. It compiles a typed pipeline to each forge's own YAML. The forge runs that YAML with nothing extra installed, and its own tooling keeps working.

| | Where the pipeline is defined | Runs in a CI job | Step isolation | Cache |
|---|---|---|---|---|
| **chant** | TypeScript, compiled to the forge's YAML | The forge's runner and the commands chant wrote | A `shell()` step can run in a container pinned by digest | The forge's |
| **[Dagger](https://dagger.io)** | Functions in modules (Go, Python, TypeScript and others) | The Dagger engine, in every job | Each operation runs in a container | Content-addressed, kept by the engine |
| **[Bazel](https://bazel.build)** | BUILD files in Starlark | Bazel, in every job | Sandboxed actions keyed by declared inputs | Local and remote, keyed by inputs |

Dagger runs the pipeline at run time. The forge's job starts the engine, and the engine runs the graph. You get the same pipeline locally and in CI, and a cache that knows each step's inputs.

Bazel is the reference for a hermetic step. An action runs in a sandbox and its cache key covers every input it declares. chant's steps don't declare their inputs today.

A generated pull-request pipeline's jobs are typed values that each forge's generator wraps, and `chant ci run --local` runs the same values without reading YAML. [github-warden](https://github.com/INTENTIUS/github-warden) reads the job names chant generates and requires them as checks, which works because the jobs are the forge's own. Where a step needs a pinned toolchain, give it an `image` ([A shell step in a container](/chant/guide/ops-reference/#a-shell-step-in-a-container)). A Dagger runtime for Ops could plug into the `opRuntime` hook as a lexicon.

## Trade-offs

- The build path doesn't apply. A chant Op deploys the artifact, locally or on a steward, or your own tooling does, such as the CloudFormation CLI, a CI pipeline, `terraform apply` or `pulumi up`.

- Static evaluation means no runtime lookups at build time. You can't call an API during synthesis to get a VPC ID or read a secret. Cross-resource references within a project work through attribute references. For a value resolved at deploy time, the lexicon has an intrinsic. For a value needed before synthesis, an agent or script can write it into a source file.

- Twenty-three lexicons ship today, and [Lexicons](/chant/lexicons/overview/) lists them. The terraform and pulumi lexicons read estates you already have, on the stock binaries or on choudoufu and plunge. [Lexicon Authoring](/chant/lexicon-authoring/overview/) covers adding one.

- The static subset of TypeScript has no function calls, no control flow around resources and no dynamic property access. That keeps synthesis deterministic. [TypeScript as Data](/chant/concepts/typescript-as-data/) lists what is supported.
