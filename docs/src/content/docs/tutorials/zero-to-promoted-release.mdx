In this tutorial you take a small workspace from a fresh repository to a release running in two environments. You make a commit green, cut a release from it, and deploy that release to staging and then prod, approving a gate in each. Everything runs on your machine against [Floci](https://floci.io), a local AWS emulator, with no AWS account.

The workspace is [`examples/trunk-curated-floci`](https://github.com/INTENTIUS/chant/tree/main/examples/trunk-curated-floci). Its one member, `infra`, synthesizes an S3 bucket and an SQS queue with the AWS lexicon and deploys them with `cfn-deploy`, one stack per environment. The declaration names the [`trunk-curated`](/chant/reference/ci-workflows/) workflow. [`test/trunk-curated-floci-e2e.sh`](https://github.com/INTENTIUS/chant/blob/main/test/trunk-curated-floci-e2e.sh) runs every step on this page.

Floci needs Docker and the aws CLI, and the rest needs git and Node.

## Start Floci

Floci listens on port 4566 inside its container. Give it a port of its own, so it can't meet another emulator already running, and point chant at it.

```bash
docker run -d -p 4597:4566 --name tutorial-floci floci/floci:latest
export AWS_ENDPOINT_URL=http://localhost:4597
export AWS_ACCESS_KEY_ID=test AWS_SECRET_ACCESS_KEY=test AWS_REGION=us-east-1
```

## Make the repository

Copy the example into a new directory and make it a repository with a remote. The remote is a bare repository next to it, so nothing leaves your machine.

```bash
mkdir tutorial && cp -R chant/examples/trunk-curated-floci/. tutorial/
git init -q --bare tutorial-origin.git
cd tutorial
git init -q -b main
git add -A && git commit -q -m "the stack"
git remote add origin "$(cd ../tutorial-origin.git && pwd)"
git push -q origin main
(cd infra && npm install)
```

Run the workspace check. It names what a real repository would still need, such as the pull-request pipeline and the publish job. In a repository of your own, [`chant ci init`](/chant/guide/trunk-curated-setup/) writes them.

```bash
npx chant workspace check
```

## Make the commit green

In a real repository, CI tags each commit that passes its required phases `ci/green/<sha>`. This one has no CI, so tag the commit by hand.

```bash
SHA=$(git rev-parse HEAD)
git tag -a "ci/green/$SHA" -m "green, by hand: this repository has no CI"
git push -q origin "ci/green/$SHA"
```

## Cut a release

From the member's directory, cut `v0.1.0` from that commit. `--at` names the commit, so your checkout could be anywhere. `--build` runs before each environment's templates are read, with `CHANT_ENV` set to that environment.

```bash
cd infra
npx chant release cut v0.1.0 --at "$SHA" --build "npx chant build src --lexicon aws -o template.json" --yes
```

The cut compiles the template once per environment and records both. It prints the release's digest and the next commands.

## Deploy staging

Write the template the release recorded for staging, and run the component under the release.

```bash
npx chant release export v0.1.0 --env staging
npx chant run --components all --env staging --release v0.1.0
```

The run stops at the component's `release` gate and prints the line that approves it. Approve it, as the person who signs off would, and run again.

```bash
npx chant approve infra release --env staging
npx chant run --components all --env staging --release v0.1.0
```

## Deploy prod

Prod is the same release, with its own template and its own gate.

```bash
npx chant release export v0.1.0 --env prod
npx chant run --components all --env prod --release v0.1.0
npx chant approve infra release --env prod
npx chant run --components all --env prod --release v0.1.0
```

Both stacks now exist:

```bash
aws --endpoint-url "$AWS_ENDPOINT_URL" cloudformation describe-stacks --query 'Stacks[].[StackName,StackStatus]' --output text
```

```
trunk-curated-staging	CREATE_COMPLETE
trunk-curated-prod	CREATE_COMPLETE
```

## Clean up

The Floci image declares a data volume, so remove it with the container.

```bash
docker rm -f -v tutorial-floci
```

## What you did

You cut one release from a green commit and ran it in two environments, approving each. Nothing you merged deployed anything. [Trunk and Releases](/chant/concepts/trunk-and-releases/#why-merge-never-deploys) explains why, and [Curate a Release](/chant/guide/curate-a-release/) picks which green commit to cut from.

A component with an artifact, such as an image, can go from staging to prod with [`chant components promote --release`](/chant/guide/promote-a-release/), which reads what staging runs. This member deploys only a template, and a run records what an environment runs only for a component that publishes an artifact, so each environment here is deployed from the release's export.
