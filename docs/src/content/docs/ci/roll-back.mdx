```sh
chant components rollback prod --release v1.3.2 --dry-run
chant components rollback prod --release v1.3.2
```

This restores every component of that release at the digest the environment ran. When a component declares a gate, the run exits 3 there. One approval passes it: `chant approve release <gate> --env prod`, then the same command again.

Roll back one component to the release before the current one, or to a given digest:

```sh
chant components rollback prod --component search-service
chant components rollback prod --component search-service --digest sha256:4c1e0b...
```

A release cut from a revoked commit is refused with `release-revoked`.

## After a deploy that applied partly

A rollback cannot finish a deploy that failed partway. `chant workspace status` shows the environment as mixed and prints the line that settles it:

```sh
chant components redeploy prod --component web
```

## Roll back in source

`chant lifecycle rollback prod --to v1.4.2` opens a change that restores `sourceDir` to that revision. It touches no cloud, and the change deploys the usual way.

[`components rollback`](/chant/cli/components/#components-rollback-env) has every flag.
