title: Evaluability Rules (EVL)
description: Rules that flag TypeScript patterns the evaluator cannot statically resolve
diataxis: reference

Evaluability rules flag TypeScript patterns that the chant evaluator cannot statically resolve. All evaluability rules have severity **error**.

EVL001 and EVL003 share one subset definition with `fold()`, the static AST reducer `chant build` uses by default (see [TypeScript as Data](/chant/concepts/typescript-as-data/#folded-vs-run)). A shape either rule flags is, with the environment-dependent exceptions below, exactly a shape the folder rejects, at the same line. EVL reports it in your editor and in `chant lint`, before a build, and `fold()` enforces it. A file the folder rejects still builds. chant imports and runs it instead, and EVL keeps that run inside the deterministic subset.

**Where EVL and `fold()` diverge.** Both import the same classifier (`fold/subset.ts`) so they can't drift on node kinds or operators, but several things depend on the environment and can't be decided from shape alone:

- **Identifier resolution** — EVL treats any bare name as valid; `fold()` alone resolves it against the file's `const`s and rejects an unbound one. A false negative on EVL's part, never the reverse.
- **Intrinsic tag registration** — EVL has no lexicon registry at lint time, so it can't tell a registered intrinsic tagged template from a made-up one; it treats any tagged-template interior as opaque. `fold()` has the registry and rejects an unregistered tag.
- **Intrinsic call-form registration** — an intrinsic its lexicon opted into call-form folding (`Ref(...)`, `Concat(...)`, or an eagerly evaluated helper such as cedar's `agentCoreStagedPolicy(...)`) folds. `chant lint` and the editor pass the active lexicons' registry to EVL, so EVL001 accepts such a call in a resource's props, and EVL004 accepts spreading the result of an eagerly evaluated one. A tool that builds a lint context without the registry gets the stricter answer and flags the call.
- **Spread-source runtime type** — EVL (via EVL004) checks that a spread source is traceable to a `const`; `fold()` additionally rejects it if that const turns out not to be an object or array at all.
- **A nested `new Type(...)` used as a property value** — shape-valid to EVL either way, but `fold()` rejects a nested resource constructor (as opposed to the top-level one being folded) as a value, because it can't be represented without constructing it, so the file falls back to run.
- **Short-circuit laziness** — `fold()` evaluates `&&`/`||`/`??`/`? :` lazily, so an unfoldable *untaken* branch doesn't reject. EVL has no notion of "taken" and requires every branch to be shape-valid. That gives false positives relative to `fold()`, never the reverse.
- **Composite step access** (chant #1544) — `Checkout({...}).step` and the same shape from any other single-action `Composite()` wrapper (a call immediately narrowed to `.step`) is the documented idiom for embedding one inline in a `Job`'s `steps:` array. EVL001 treats it as shape-valid; `fold()` still can't fold it (a call is not a value it can reduce) and falls the file back to the run path, as documented. The fallback was always valid; EVL001 used to flag it by mistake.

In practice EVL catches the same code. These are the edge cases where code that passes lint can still fail to fold, or EVL flags code `fold()` would accept.

## EVL001: Non-Literal Expression

Resource property values must be statically evaluable. Function calls, method calls, and other dynamic expressions are not allowed.

```typescript
// ❌ Triggers EVL001
export const bucket = new _.Resource({
  bucketName: getName(),
  tags: Object.assign({}, baseTags),
});
```

```typescript
// ✅ Fixed
const name = "my-data-bucket";
const tags = { ...baseTags, env: "prod" };

export const bucket = new _.Resource({
  bucketName: name,
  tags: tags,
});
```

```typescript
// ✅ Also allowed — a Composite() wrapper's `.step` output embedded inline
// (chant #1544; see "Where EVL and fold() diverge" above)
export const build = new Job({
  "runs-on": "ubuntu-latest",
  steps: [Checkout({}).step, new Step({ name: "Test", run: "npm test" })],
});
```

## EVL002: Control Flow Wrapping Resources

Resource instantiation cannot appear inside control flow blocks (`if`, `for`, `while`, `switch`, `try`). Resources must be declared at the top level.

```typescript
// ❌ Triggers EVL002
if (env === "prod") {
  export const bucket = new _.Resource({
    bucketName: "prod-data",
  });
}
```

```typescript
// ✅ Fixed
export const bucket = new _.Resource({
  bucketName: "my-data",
});
```

---

## EVL003: Dynamic Property Access

Computed property access with a non-literal key cannot be evaluated statically.

```typescript
// ❌ Triggers EVL003
const region = config[key];
```

```typescript
// ✅ Fixed
const region = config["production"];
```

## EVL004: Spread From Non-Const Source

The spread operator requires the source to be traceable to a `const` declaration. A binding imported from another module counts, so an exported `const` can be shared and spread across modules. So does a call to a helper an active lexicon registered as eagerly evaluated, such as cedar's `...agentCoreStagedPolicy(...)`, because the folder calls it and spreads the object it returns.

```typescript
// ❌ Triggers EVL004
export const bucket = new _.Resource({
  ...getDefaults(),
});
```

```typescript
// ✅ Fixed
const defaults = { versioning: true, encryption: "AES256" };

export const bucket = new _.Resource({
  ...defaults,
});
```

## EVL005: Block Body in resource() Callback

Callbacks passed to `resource()` must use expression body syntax. Block bodies with `return` statements cannot be statically evaluated.

```typescript
// ❌ Triggers EVL005
resource(_.Resource, (props) => {
  const name = props.name + "-data";
  return { bucketName: name };
});
```

```typescript
// ✅ Fixed — use expression body
resource(_.Resource, (props) => ({
  bucketName: props.name + "-data",
}));
```

---

## EVL007: Invalid Siblings Access

In composite resources, accessing `siblings.key.attr` where `key` does not exist in the resource map is an error.

```typescript
// ❌ Triggers EVL007
resource(_.ServiceType, (props, siblings) => ({
  role: siblings.typo.arn,
}));
```

```typescript
// ✅ Fixed
resource(_.ServiceType, (props, siblings) => ({
  role: siblings.executionRole.arn,
}));
```

## EVL012: Pipeline Declaration Does Not Fold

A member's `.chant/pipeline.ts` is folded to its spec and never run, so it holds imports from `@intentius/chant/pipeline`, `const`s of literals and one `export default pipeline({ ... })`. EVL012 runs the same fold `chant build` runs and reports its finding at the same line. An expression outside the subset keeps the id the classifier gives it (EVL001, EVL003); a statement of another kind, an import from another module, or a declaration the spec check refuses is EVL012. Unlike a resource file, a pipeline file that does not fold stops the build. See [Pipeline](/chant/reference/pipeline/).

```typescript
// ❌ Triggers EVL012
import { pipeline } from "@intentius/chant/pipeline";
let runner = "ubuntu-latest";
export default pipeline({ name: "shop", defaults: { op: "shop", runner }, stages: [] });
```

```typescript
// ✅ Fixed
import { pipeline } from "@intentius/chant/pipeline";
const runner = "ubuntu-latest";
const dev = { name: "dev", waves: [{ name: "dev", runs: [{ target: "dev" }] }] };
export default pipeline({ name: "shop", defaults: { op: "shop", runner }, stages: [dev] });
```
