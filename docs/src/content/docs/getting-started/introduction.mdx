This page covers the same ground as the [Overview](/chant/concepts/overview/), with paths to start from.

chant is a TypeScript-first infrastructure tool. You define cloud resources as plain TypeScript objects; chant type-checks them against a provider lexicon and writes deployment-ready output such as CloudFormation or Kubernetes YAML. It can also deploy that output and then watch it for drift or reconcile it. You write TypeScript, and ownership lives in markers on the cloud resources.

```
TypeScript source → chant build → provider-specific output
```

The build is deterministic. Lexicons plug in on the input side, and you choose what runs after the build, per environment. The two sides differ today: lexicons are a shipped plugin contract, while a lifecycle is something you compose from Ops (plugging in a foreign backend is planned, not shipped). See the [Overview](/chant/concepts/overview/) for the whole design, or [Lifecycle Models](/chant/concepts/lifecycle-models/) for the dial in depth.

chant computes a create/update/delete plan against the live system from ownership markers on the cloud resources ([State and Governance](/chant/concepts/governance/)). When an apply needs an approval that waits on a person, a rollback or a cadence, declare it as an [Op](/chant/concepts/durable-workflows/). An Op runs in-process by default and on a hosted runtime when you ask.

You get real `import`/`export`, editor autocompletion and semantic lint rules that catch misconfigurations before deployment, in one local pass.

## Choose Your Path

- With a coding agent, hand it the [copy-paste prompt](/chant/agents/). It installs chant, runs `chant init`, and reads the generated skills before writing anything.
- To learn hands-on, work through the [getting-started example](https://github.com/INTENTIUS/chant/tree/main/examples/getting-started). It teaches chant in levels, starting with typed resources, `chant build` and the YAML it writes, and building up to deployment. Run it alongside [Quick Start](/chant/getting-started/quick-start/).
- For deployments with phase visibility, gate steps and rollback, declare phases in `*.op.ts`. `chant run` executes them in-process or on a steward. Start with [Quick Start](/chant/getting-started/quick-start/), then the [Ops guide](/chant/guide/ops/). [Choosing Your Deployment Model](/chant/concepts/deployment-paths/) helps you decide whether Ops fits.
- To track drift and reconcile it, pick a position per environment on the `observe → reconcile → authoritative` dial: report drift, open `cloud → code` PRs, or apply `code → cloud` behind a gate. See [Lifecycle Models](/chant/concepts/lifecycle-models/) and the [Reconciling Lifecycle](/chant/guide/reconciling-lifecycle/) guide.
- If you have many deployable units (services, tables, clusters, libraries), declare them in `*.component.ts`. One orchestrator builds, publishes, signs, applies and rolls back each, with no pipeline per unit. See [Components](/chant/concepts/components/) and [Supply-Chain Attestations](/chant/components/supply-chain/).
- Terraform and OpenTofu roots join a workspace through the [terraform lexicon](/chant/lexicons/terraform/), which reads them as they are, and [choudoufu](/chant/lexicons/terraform/ops/#choudoufu) runs them with ownership markers. A Pulumi program joins through the [pulumi lexicon](/chant/lexicons/pulumi/), and [plunge](/chant/lexicons/pulumi/plunge/) runs it the same way. See [Works with](/chant/concepts/comparison/).
- If you already have CI, ArgoCD or another deploy tool, chant writes typed, linted artifacts for it and you skip the lifecycle stages. [Quick Start](/chant/getting-started/quick-start/) covers this path. Lexicons are available for [AWS](/lexicons/aws/), [Azure](/lexicons/azure/), [GCP](/lexicons/gcp/), [Kubernetes](/lexicons/k8s/), [Helm](/lexicons/helm/), [k3d](/lexicons/k3d/), [k3s](/lexicons/k3s/), [Docker](/lexicons/docker/), [GitHub Actions](/lexicons/github/), [GitLab CI](/lexicons/gitlab/), [Forgejo](/lexicons/forgejo/), [Fly Machines](/lexicons/fly/), [Fountain](/lexicons/fountain/), [E2B](/lexicons/e2b/), [Render](/lexicons/render/), [Control Plane](/lexicons/cpln/), [Cedar](/lexicons/cedar/), [Terraform](/lexicons/terraform/), and [Pulumi](/lexicons/pulumi/).
- Lexicon authors read [Philosophy](/chant/concepts/philosophy/) for the design rationale, then [Lexicon Authoring](/chant/lexicon-authoring/overview/) to build a plugin.
- Contributors start with [Development Setup](/chant/contributing/development/), then the [Architecture Overview](/chant/architecture/overview/).
