To deploy **one composite to several environments, with per-environment
differences**, layer its config. [Presets](/chant/guide/presets/) cover one
level of shared defaults spread into resources. Layered configuration is a base
config that each environment overrides, nested objects included. It is plain
TypeScript object spread in one file, with no merge helper or codegen.

## The pattern

## Why it resolves at synthesis

chant's [evaluability rules](/chant/concepts/where-values-come-from/) (EVL)
require resource inputs to resolve to static data. Object spread from a `const`
qualifies, at any depth:

- `{ ...base, replicas: 6 }` — const spread. Allowed (the same rule presets use).
- `{ ...base.labels, "acme.io/env": "prod" }` — **static member-access spread**.
  Allowed: reading a known property of a `const` is static. Only a *computed*
  access like `config[key]` is rejected (EVL003).
- `deepMerge(base, prod)` — a **function-call** initializer. Rejected by EVL004.
  This is the one thing that does not work, and it is why the pattern uses native
  nested spread instead of a merge helper.

So the shallow level is `...base` and each nested object you want to merge gets
its own `...base.<key>`. A nested object you *don't* spread is replaced
wholesale, the same rule presets follow. That is often what you want
(`securityContext` in the example is set once on the base and inherited
unchanged).

## Stable per-environment names

Give each environment its own `name` so resources don't collide in a single
build. In the example the base deliberately omits `name`, and each environment
supplies its own (`web-dev`, `web-staging`, `web-prod`). Thread an `env` or
`name` through the composite the same way for any multi-environment stack.

## When you outgrow it

This pattern stays in plain TypeScript on purpose: every environment is an
explicit object you can read and audit, and the build is deterministic. To see
the *effective* config for one environment, run
[`chant describe`](/chant/cli/describe/).

## Try it

The full example is
[`lexicons/k8s/examples/layered-config`](https://github.com/INTENTIUS/chant/tree/main/lexicons/k8s/examples/layered-config)
and CI builds it.

```bash
cd lexicons/k8s/examples/layered-config
npm install
npm run build   # → k8s.yaml (three environments)
npm run lint    # the gate — clean
```
