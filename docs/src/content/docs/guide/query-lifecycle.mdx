chant keeps its records on the `chant/lifecycle` branch. [`chant query`](/chant/cli/query/) loads them into SQLite in memory and runs one statement. Nothing is written, and the database is gone when the command exits.

## Get the records

The command reads the local branch. To query what CI recorded, fetch it first:

```
git fetch origin chant/lifecycle:chant/lifecycle
```

To read the branch as it was at an earlier commit, pass `--at` with a ref or a date:

```
chant query "SELECT env, count(*) FROM resources GROUP BY env" --at chant/lifecycle~10
chant query "SELECT env, count(*) FROM resources GROUP BY env" --at 2026-10-01
```

A date reads the newest ledger commit at or before the end of that day.

## List what is deployed

The `resources` table has one row per resource in each environment's snapshot, from the lexicon that observed it:

```
chant query "SELECT env, lexicon, type, count(*) AS n FROM resources GROUP BY env, lexicon, type ORDER BY n DESC"
```

An attribute a lexicon read is in the `attributes` JSON:

```
chant query "SELECT name, json_extract(attributes, '$.Arn') AS arn FROM resources WHERE env = 'prod' AND lexicon = 'aws'"
```

`snapshots` says when each environment was last observed, and at which commit:

```
chant query "SELECT env, lexicon, observed_at, git_sha FROM snapshots ORDER BY observed_at"
```

## Find failed runs

```
chant query "SELECT op, env, started, failure_code, failure_reason FROM runs WHERE status = 'fail' ORDER BY started DESC LIMIT 10"
```

## See who approved a deploy

A deploy record names its release, and a gate resolution names the release it approved. Join them:

```
chant query "SELECT d.env, d.component, d.timestamp, g.resolved_by FROM deploys d LEFT JOIN gates g ON g.kind = 'resolution' AND g.release_digest = d.release_digest AND g.environment = d.env ORDER BY d.timestamp DESC"
```

Gates still waiting:

```
chant query "SELECT op, gate, timestamp, expires_at FROM gates WHERE kind = 'pending' AND expires_at > strftime('%Y-%m-%dT%H:%M:%SZ', 'now')"
```

## Label deploys with their release

```
chant query "SELECT d.env, d.component, c.label, d.timestamp FROM deploys d JOIN cuts c ON c.release_digest = d.release_digest ORDER BY d.timestamp DESC"
```

## Read the other ledgers

The other ledgers chant writes have tables too. A ConvergeOp writes one `converge` row per tick, with the tick's counts:

```
chant query "SELECT env, op, timestamp, drifted, remediated, gated FROM converge WHERE drifted > 0 ORDER BY timestamp DESC LIMIT 20"
```

A promote, rollback or redeploy that failed or stopped at a gate writes a deploy outcome, and `deploy_outcomes` has a row for each of its components:

```
chant query "SELECT env, verb, component, outcome, timestamp FROM deploy_outcomes WHERE outcome IN ('failed', 'gated') ORDER BY timestamp DESC"
```

Each change set a gate stored is in `change_sets`, and its entries are in `change_set_entries`. This lists the deletes and replacements the gates bound:

```
chant query "SELECT digest, set_member, address, action FROM change_set_entries WHERE action IN ('delete', 'replace')"
```

`builds` has one row per build manifest and `build_artifacts` one per entry. An SBOM entry names the artifact it describes in `subject_digest`:

```
chant query "SELECT b.component, a.path, a.generator, a.package_count FROM builds b JOIN build_artifacts a ON a.manifest_digest = b.manifest_digest WHERE a.kind = 'sbom'"
```

`leases` holds every claim, renew and release of a work lease:

```
chant query "SELECT item, event, holder, timestamp, outcome FROM leases ORDER BY timestamp"
```

## Query a workspace

In a workspace every row has the member it came from. `--member` reads only the members it names:

```
chant query "SELECT member, count(*) FROM deploys GROUP BY member"
chant query "SELECT * FROM runs" --member api
```

## Use the rows in a script

`--json` prints the columns, the rows and the schema version. A script that depends on the columns can check the version first:

```
chant query "SELECT DISTINCT version FROM chant_schema" --json
```

The [reference](/chant/cli/query/#tables) lists every table and column. A product that keeps records of its own can add its tables beside these, as the [reference](/chant/cli/query/#a-products-own-tables) shows.
