Every security feature in chant is off until a workspace turns it on ([#4168](https://github.com/INTENTIUS/chant/issues/4168)). A group turns on a set of them at once, and each feature still turns on alone; the [security features reference](/chant/reference/security-features/) lists them all.

Under `supply-chain`:

- A publish target with no SBOM source is refused (`publish-sbom-missing`). Without the group it publishes without one.
- A publish with no OIDC token warns that what it publishes carries no provenance. Without the group, provenance is only a field in the plan. `--require-provenance` refuses instead, with or without the group.

An SBOM comes from the file a target's `sbom` names, else from the lockfile nearest the member: `package-lock.json`, `pom.xml` or `Cargo.lock`. A member whose directory holds a `Cargo.toml` reads `Cargo.lock` first.

## Opt in

Add the group to `security` in `chant.workspace.json`, at the top level for every member or on one member for that member only. A member's list adds to the top-level one.

```json
"security": ["supply-chain"]
```

A declaration that uses `security` sets `minReader` to `0.124.33` or newer.

## Fill the gaps

`chant workspace check` reports what the group still lacks as `WSP162` warnings:

| Code | What to do |
|---|---|
| `security-sbom-disabled` | Remove `sbom: false` from the publish target. |
| `security-sbom-unsourced` | Point `sbom` at the SPDX or CycloneDX file the build writes, or commit the member's lockfile. |
| `security-publish-no-provenance` | Pass `--require-provenance` in the publish job, which runs in CI with an OIDC token. |
| `security-component-no-sbom` | Add a `generateSbom` step to the member's components. |
| `security-component-no-verify` | Add a `verify` step before the deploy steps. |
