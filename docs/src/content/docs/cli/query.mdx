## Synopsis

```
chant query "<sql>" [dir] [--member <name>] [--json]
```

## Description

`chant query` loads the local `chant/lifecycle` branch into an in-memory SQLite database and runs one statement over it ([#4297](https://github.com/INTENTIUS/chant/issues/4297)). The inventory comes from the snapshots each lexicon's `describeResources` wrote, so it works for every lexicon.

```
$ chant query "SELECT env, lexicon, count(*) AS n FROM resources GROUP BY env, lexicon"
env   lexicon  n
----  -------  --
prod  aws      14
prod  k8s      6
(2 rows)
```

Only a statement that begins with `SELECT`, `WITH` or `VALUES` runs, and the database takes `PRAGMA query_only`, so nothing is written (`packages/core/src/lifecycle/query.ts:270` and `:285`). It reads the local branch and never fetches. Run `git fetch origin chant/lifecycle:chant/lifecycle` first to query what CI recorded.

Inside a workspace the command reads every member's ledger and each row names its member, as `packages/core/src/cli/handlers/query.ts:44` sets it. Outside a workspace it reads the project's own ledger and leaves `member` NULL. The engine is the SQLite built into Node from version `22.13`, `node:sqlite`.

For a reader that needs a contract, such as an agent or another product, use [`chant ledger`](/chant/cli/ledger/) instead: the same tables and rows as a JSON read contract, filtered with typed `--where`, `--since` and `--at` filters and no SQL engine ([#4363](https://github.com/INTENTIUS/chant/issues/4363)). `chant query` stays as it is for now, since terragucci reads through it.

## Tables

Every table starts with `member`. A column marked JSON holds JSON text for `json_extract`, and a column is TEXT unless it is marked INTEGER.

| Table | One row per | Columns |
|---|---|---|
| `resources` | resource in an environment's snapshot | `env`, `stack`, `lexicon`, `name`, `type`, `physical_id`, `status`, `last_updated`, `ownership`, `attributes` (JSON), `git_sha`, `observed_at`, `marker_stack`, `marker_env`, `engine_ownership`, `engine_owned_by` (see [Ownership](#ownership)) |
| `snapshots` | snapshot file, `<env>/<lexicon>.json` or `<env>/<stack>__<lexicon>.json` | `env`, `stack`, `lexicon`, `git_sha`, `observed_at`, `depth`, `resources` (INTEGER), `unobserved` (INTEGER) |
| `runs` | Op run record, `<env>/runs__<op>.jsonl` | `id`, `op`, `env`, `started`, `ended`, `status`, `git_sha`, `forge`, `run_url`, `failure_code`, `failure_reason`, `failed_phase`, `gate`, `steward`, `labels` (JSON), `outcomes` (JSON), `root_member`, the member whose directory holds the root a TerraformApplyOp run applied ([#4482](https://github.com/INTENTIUS/chant/issues/4482)) |
| `gates` | gate ledger line, `_gates/<op>.jsonl` | `op`, `gate`, `kind` (`pending` or `resolution`), `timestamp`, `resolved_by`, `relayed_by`, `approver_kind`, `plan_digest`, `environment`, `release_digest`, `git_sha`, `run_id`, `url`, `note`, `expires_at`, `origin`, `empty` (INTEGER), `signed` (INTEGER) |
| `deploys` | deploy record, `<env>/releases.jsonl` | `env`, `component`, `digest`, `git_sha`, `run_id`, `forge`, `run_url`, `timestamp`, `actor`, `approver`, `release_digest`, `digest_kind`, `promoted_from` (JSON), `restores` (JSON), `redeploys` (JSON) |
| `releases` | release file, `_releases/<digest>.json` | `release_digest`, `release_member`, `git_sha`, `envs` (comma list), `artifacts` (JSON) |
| `cuts` | line of `_releases/cuts.jsonl` | `release_digest`, `label`, `actor`, `timestamp`, `run_id`, `forge`, `channel`, `signed` (INTEGER), `composed_base` |
| `chant_schema` | column of every table above | `version` (INTEGER), `table_name`, `column_name`, `type`, `position` (INTEGER) |

The columns are listed in `QUERY_TABLES` (`packages/core/src/lifecycle/query.ts:49`).

## Ownership

Four columns of `resources` say who holds a resource, beside `ownership`
([#4534](https://github.com/INTENTIUS/chant/issues/4534)). `ownership` is chant's
verdict from the resource's marker: `owned`, `foreign` or `unknown`.
`marker_stack` and `marker_env` are the stack and env that marker names, read off
the resource, and are NULL when the read carries no marker or the lexicon's
channel does not return one. On aws's stack read every resource of a marked
stack carries that stack's identity. `engine_ownership` and `engine_owned_by` are
an ownership engine's own answer, from the engine facts a choudoufu live root or a
plunge member records: `bound`, `unowned`, `pending` or `foreign`, and `marker`,
`record` or `name` for what bound it. They are NULL for every other resource.
chant decides nothing from them. A pulumi member stays `unknown` in `ownership`,
because chant reads plunge's records and not its markers, so its answer is in the
engine columns.

```
chant query "SELECT member, env, lexicon, ownership, engine_ownership, count(*) AS n FROM resources GROUP BY 1, 2, 3, 4, 5"
chant query "SELECT member, env, stack, name, ownership, marker_stack FROM resources WHERE physical_id = 'i-0abc123'"
```

The four columns were added within version 1, written by chant 0.124.54 and newer, so a row that an older chant's snapshot holds has all four NULL and reads as unknown.

## Schema version

The tables are a contract at version 1 (`QUERY_SCHEMA_VERSION`, `packages/core/src/lifecycle/query.ts:39`). A column can be added within a version. Renaming or removing one, or changing what it holds, makes a new version. `chant_schema` carries the version on every row, and `--json` prints it as `schemaVersion`, so a saved query can check what it runs against:

```
chant query "SELECT DISTINCT version FROM chant_schema"
```

## What is left out

Each ledger is parsed by the reader its own commands use, and a line or file that is not its kind is left out and counted. The text output warns with the counts on stderr, and `--json` prints them under `malformed`. A release file whose content does not hash to its digest counts as malformed, as `readAllReleases` counts it (`packages/core/src/lifecycle/query.ts:223`). Other JSON files beside the snapshots, such as the observation baseline, are skipped (`packages/core/src/lifecycle/query.ts:175`).

## Options

| Option | Meaning |
|---|---|
| `"<sql>"` | The statement, quoted as one argument. |
| `dir` | Where to read from. The default is the current directory. |
| `--member <name>` | Only this member. Repeat it, or give a comma list, for several. |
| `--json` | Print `{ schemaVersion, columns, rows, tables, malformed }`. `tables` counts each table's rows. |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | The statement ran. |
| 1 | No statement, a statement that writes or does not parse, a `--member` that names no member, or a Node with no `node:sqlite`. |
