## Synopsis

```
chant operator [flags]
chant operator status [flags]
chant operator log [flags]
chant approve <op> <gate> [flags]
```

## Description

`chant operator` runs scheduled ticks for every discovered [`ConvergeOp`](/chant/guide/converging-lifecycle/) locally, with no new service and no new state store. Coordination is a git-ref lease; tick state is a ledger fact on the `chant/lifecycle` orphan branch. See the [Operator guide](/chant/guide/operator/) for the full design (pipeline vs converge ops, the lease, crash recovery, gate-as-fact).

`chant approve` is the sibling command that records a gate's out-of-band resolution — the durable counterpart to a tick's `gated` outcome.

## Subcommands

### `operator`

Tick every discovered `ConvergeOp`, on `--interval`, until Ctrl-C.

```bash
chant operator
chant operator --env staging
chant operator --interval 30s --lease-ttl 2m
chant operator --once
```

| Flag | Default | Meaning |
|---|---|---|
| `--env <name>` | all | Scope discovery to ConvergeOps declaring this environment (`labels.Env`) |
| `--interval <duration>` | `60s` | How often the daemon runs a round. Accepts the same duration syntax as an activity profile timeout (`30s`, `5m`, `1h30m`) |
| `--lease-ttl <duration>` | `5m` | How long an acquired lease is valid before another operator can reclaim it |
| `--steward [<name>]` | off | Run a declared steward's scheduled Ops instead of the ConvergeOps. See below |
| `--once` | off | Run a single round and exit, instead of looping. Exits non-zero if any op's tick failed this round. What a cron job, CI step, systemd timer, or Kubernetes CronJob should pass — the daemon form (`--once` omitted) is for a machine that stays up |

Each round prints one line per discovered `ConvergeOp`:

```
operator: staging-converge@staging ticked=1 ok=true
operator: prod-converge@prod skipped=1(lease-held:mac.local:4821:9f2c1a3b)
operator: nightly-converge@prod skipped=1(not-due:0 3 * * *)
```

A `ConvergeOp` that declares its own `schedule` cron is ticked on that cron rather than on every round: the daemon still wakes on `--interval`, but an op whose cron has not fired since the operator last looked at it is skipped as `not-due`. `--interval` is the fallback for an op with no cron of its own, and the resolution at which any cron can be honoured — a round that runs every five minutes cannot see a per-minute cron.

#### `operator --steward [<name>]`

Run a declared steward's local form instead of every ConvergeOp ([#2731](https://github.com/INTENTIUS/chant/issues/2731)). A steward is the one writer for an environment: on Fountain it is the fountain lexicon's `Steward` Agent and Teammate, and on a box with no Fountain behind it, it is this command. The declaration is found in the project's `*.op.ts` files, from `declareSteward` in `@intentius/chant/op` or the fountain `Steward`'s `declaration`.

```bash
chant operator --steward                         # the project's only steward
chant operator --steward box-steward --env minimal
chant operator --steward box-steward --once
```

The command refuses to start when the steward's form in `--env` (default `local`) is `fountain`, since the Fountain teammate is the steward there, and when another live process holds the steward's lease, `refs/chant/lease/_stewards/<name>`. Each round renews that lease and then runs the steward's scheduled Ops, each on its own cron and under its own operator lease, as the ConvergeOp rounds above do. An Op with no schedule is left for someone to run by hand. Each run lands on the run ledger. A round that finds the steward's lease held by another process ticks nothing and prints `operator: steward <name> skipped=1(steward-lease-held:<holder>)`. `--interval`, `--lease-ttl` and `--once` work as they do without `--steward`. The lease is released on Ctrl-C or SIGTERM.

`chant workspace status --json` reports the steward with its lease and the last run of each Op. [The Steward](/chant/lexicons/fountain/steward/) covers the declaration and how the steward shares a checkout with a coding agent.

### `operator status`

Print the last tick, outcome counts, and pending gates for every discovered `ConvergeOp`, read from the ledger alone — no daemon needs to be running.

```bash
chant operator status
chant operator status --env staging
chant operator status --json
```

| Flag | Meaning |
|---|---|
| `--env <name>` | Scope to ConvergeOps declaring this environment |
| `--json` | Emit the same data as a JSON array instead of the human-readable form |

### `operator log`

The history behind `status`. Every tick record for the discovered `ConvergeOp`s and every gate resolution against them, merged into one timeline ordered by timestamp, oldest first, read from the `chant/lifecycle` orphan branch. No daemon needs to be running.

```bash
chant operator log
chant operator log --env staging --op staging-converge
chant operator log --since 2026-08-25T00:00:00Z --limit 50 --json
```

| Flag | Meaning |
|---|---|
| `--env <name>` | Scope to ConvergeOps declaring this environment |
| `--op <name>` | Restrict to one ConvergeOp by name. Omitted, every discovered ConvergeOp's ticks are merged |
| `--since <iso>` | Keep entries at or after this ISO-8601 instant. Inclusive |
| `--limit <n>` | Keep only the newest `n` entries. They still print oldest-first |
| `--json` | Emit `{ entries, malformed }` as one document on stdout. `malformed` counts ledger lines that could not be parsed, per ledger, so a shorter timeline is never silent |

Each tick line carries the tick's own id in brackets, so an outcome can be traced back to the tick that produced it. See the [Operator guide](/chant/guide/operator/#chant-operator-log) for the output format.

### `approve <op> <gate>`

Record a gate's out-of-band resolution — the durable counterpart to a converge tick's `gated` outcome (see the [Operator guide's Gate-as-fact section](/chant/guide/operator/#gate-as-fact)).

```bash
chant approve fountain-apply rollout-gate
chant approve fountain-apply rollout-gate --actor alex --url "https://github.com/org/repo/pull/123"
chant approve fountain-apply rollout-gate --note "paged on-call first; see the incident channel"
```

| Flag | Default | Meaning |
|---|---|---|
| `--actor <name>` | `$GITHUB_ACTOR` / `$GITLAB_USER_LOGIN` / `$USER` | Who resolved the gate — recorded on the resolution fact |
| `--url <url>` | the surrounding CI job's PR/MR, when there is one | The address this resolution happened at, typically the PR or MR that carried the change. Recorded typed on the resolution fact so a reader is not sniffing free text for a link. Must be an absolute http or https URL |
| `--note <text>` | — | Free-text context recorded alongside the resolution. The link belongs in `--url`; this is for everything else |
| `--env <env>` | the newest pending fact's environment | For a component gate: which environment's pending fact to approve. The resolution records that environment and its plan digest ([#2574](https://github.com/INTENTIUS/chant/issues/2574)). Ignored for an Op gate |

Recording a resolution does not resume a run that already stopped. Nothing is parked waiting for it. The run read the ledger, found nothing standing, and exited 3 after writing the pending fact. Run the Op again and it reads the resolution you just wrote and walks through the gate, or let the merged PR the note points at carry the change itself.
