## Synopsis

```
chant workspace graph [dir] [-o <file>] [--member <name>] [--env <name>] [--dry-run]
```

## Description

`chant workspace graph` reads every member of kind `chant` through that member's own `chant graph --format ir` and composes the results into one document ([#2537](https://github.com/INTENTIUS/chant/issues/2537), [ws-009](https://github.com/INTENTIUS/chant/blob/main/docs/design/decisions/ws-009-ir-versions.md), [ws-018](https://github.com/INTENTIUS/chant/blob/main/docs/design/decisions/ws-018-composer.md), [ws-022](https://github.com/INTENTIUS/chant/blob/main/docs/design/decisions/ws-022-ids.md)). The toolchain each member gets works as described for [`chant workspace build`](/chant/cli/workspace-build/#which-chant-runs-a-member). Example groups have no place in the graph.

[`chant graph`](/chant/cli/graph/) is unchanged. At a workspace root it still prints the single-project IR of the root project, and this command is the only place members are composed.

## Composition

Every node id becomes `<member>/<id>`. Member names can't contain `/`, and `::` keeps its meaning for stacks inside a member, as in `app/web::Bucket`. Edge ends and `$ref` values in attributes are rewritten the same way, as are `compositeInstance`, `runtimeOwner` and the nodes of exports and imports. Each node and edge also gains a `member` field.

`groups.byMember` maps each member to its node ids. A lexicon or a composite type means the same thing in every member, so `byLexicon` and `byComposite` keep their keys and merge the ids across members. The keys of `byStack`, `byContainer` and `byWave` name things inside one member, and they are prefixed with the member too.

The `links` and `records` sections are where member links and record kinds will go. They are empty in this release.

A member's IR with no `version` field comes from a chant older than that field. It is read as version 1 and upgraded in place, and the member's entry has `irVersion: null`. An IR with a version newer than this chant reads is left out with the reason code `ir-version-unsupported`.

## Output

```json
{
  "version": 1,
  "workspace": { "name": "acme", "root": "/work/acme" },
  "members": [
    { "name": "api", "dir": "services/api", "kind": "chant", "status": "composed", "reason": null, "chant": "0.80.0", "irVersion": 1 },
    { "name": "legacy", "dir": "legacy", "kind": "chant", "status": "composed", "reason": null, "chant": null, "irVersion": null },
    { "name": "docs", "dir": "docs", "kind": "other", "status": "skipped", "reason": { "code": "kind-not-run", "message": "..." }, "chant": null, "irVersion": null }
  ],
  "nodes": [{ "id": "api/apiNs", "kind": "Namespace", "lexicon": "k8s", "attrs": {}, "member": "api" }],
  "edges": [],
  "groups": {
    "byMember": { "api": ["api/apiNs"], "legacy": ["legacy/Queue"] },
    "byLexicon": { "k8s": ["api/apiNs"] }
  },
  "exports": [],
  "imports": [],
  "links": [],
  "records": []
}
```

`version` is the version of the composed document. A member's `chant` is the version its toolchain reported, or `null` when the member was read by a chant older than `member-run`. A member's `meta` and `pipeline`, when its IR has them, stay on the member's entry.

### Reason codes

| Code | The member |
|---|---|
| `kind-not-run` | has a kind the workspace commands don't run, such as `other` |
| `dir-missing`, `unknown-kind`, `kind-probe-failed` | can't be read, as [`chant workspace ls`](/chant/cli/workspace-ls/#reason-codes) reports |
| `command-failed` | printed no graph, because its `chant graph` exited with a failure |
| `output-unreadable` | printed something that is not a graph IR |
| `ir-version-unsupported` | printed an IR newer than this chant reads |

## Options

| Option | Effect |
|---|---|
| `dir` | Where the walk up to the declaration starts. |
| `-o, --output <file>` | Write the document to a file. |
| `--member <name>` | Compose only these members. Repeatable, and a comma list works too. |
| `--env <name>` | Passed to each member's `chant graph`. |
| `--dry-run` | Print the plan and read nothing. |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Every `chant` member was composed. |
| 1 | A member failed or couldn't be read, or the declaration couldn't be read. The document is still printed, with the failed members listed. |
