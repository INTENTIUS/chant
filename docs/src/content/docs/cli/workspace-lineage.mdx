## Synopsis

```
chant workspace lineage [--json]
chant workspace lineage resolve <path>
```

## Description

`chant workspace lineage` reads [`.chant/workspace.lock.json`](/chant/reference/lineage-lock/) in the current directory and prints one entry per scope. Each entry names the scope's template and pin. It then counts the files the project has edited or deleted since, and lists open manual steps. Generated files are left out of the counts, because their command rebuilds them.

It needs no `chant.workspace.json`. Any project with a lock can use it, including a plain project made by `chant init --from`. The command exits 1 when there is no lock.

```
$ chant workspace lineage
.  template  github.com/acme/starter#service@v1.4.0 (4624a0b6ca83)
  12 file(s), 2 edited, 0 deleted
vendor/web-app  vendor web-app  local:../shared/web-app@v1.2.0
  3 file(s), 1 edited, 0 deleted
  manual step: vendor/web-app/index.ts (changed-locally)
2 scope(s), 1 manual step(s) open
```

## `resolve <path>`

Closes the manual step for `<path>`, given relative to the lock's directory. Run it after merging the source's changes into the file by hand. The file as it stands is kept, and the source's version becomes its new merge base. For a file the source removed, the file leaves the lineage and stays as the project's own. The command exits 1 when `<path>` has no open step.

## Options

| Option | Effect |
|---|---|
| `--json` | Print `{ lock, scopes }`, where each scope has `scope`, `kind`, `name` (vendor only), `template`, `ref`, `address`, `files` (a count), `edited`, `missing` and `manualSteps`. |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | The lock was read, or the step was closed |
| 1 | No lock, an invalid lock, or no open step for the path |
