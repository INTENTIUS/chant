A release catalog lists every component a repository publishes and every version of each, with the facts a consumer checks before pinning one. It is read from the [release ledger](/chant/reference/workspace-read-contract/) only: each publish appends a release record, and the catalog groups those records by component and version ([#4595](https://github.com/INTENTIUS/chant/issues/4595)). A product writes the catalog beside its registry and renders it as a static site. terragucci writes it under `<prefix>/catalog/` for its module registry, and plywood can use the same code for npm packages, since core carries no engine word.

The model lives in `packages/core/src/lifecycle/release-catalog.ts` and the site in `packages/core/src/lifecycle/release-catalog-site.ts`, imported as `@intentius/chant/lifecycle/release-catalog` and `@intentius/chant/lifecycle/release-catalog-site`, with the schema at `packages/core/src/workspace/release-catalog.schema.json`. Both need chant 0.124.55 or newer (`RELEASE_CATALOG_FLOOR`), so a product reaches them through a feature-detect until that release ships.

## Release versions

A release record already uses `version` for its schema version (always `1`). The version a publish gives a release, such as `1.4.0` for a module or `2.0.0-rc.1` for a package, is recorded as `releaseVersion`. chant 0.124.55 and newer write and read it (`RELEASE_VERSION_FLOOR`). A record without it still parses, and the catalog lists that release by its digest. A value that is not a non-empty string is refused by `appendReleaseRecord` and dropped on read, so the rest of the record still reads.

## Catalog input

`buildReleaseCatalog(input, { generatedAt, chant })` takes:

| Input | Joined by | Gives each version |
|---|---|---|
| `releases` | component, then `releaseVersion` or digest | `digest`, `commit`, `time` (the earliest record), `actor`, `envs` |
| `statuses` | digest, else version | `status`: the latest record by time wins, so a restore is one more record with `active` |
| `changelogs` | version or digest | `changelog`: `bump` and `entries` |
| `consumers` | version or digest | `consumers`: repo, root, file and address of each call |
| `attestations` | digest | `attestation`: `verified`, `signed` or `unsigned`, the `verify` command, the signing identity |
| `fields` | component, or version or digest | `fields[<engine>]`, merged per engine key |

An input that matches no release is left out. The builder validates its result against the schema and throws `ReleaseCatalogError` with one line per problem, so an engine field JSON cannot hold fails before anything is written. `parseReleaseCatalog(text)` reads a catalog back and keeps any field this chant does not know.

## Document shape

```json
{
  "$schema": "https://intentius.io/chant/schemas/workspace/release-catalog/v1/release-catalog.schema.json",
  "contract": 1,
  "chant": "0.125.0",
  "generatedAt": "2026-10-27T00:00:00.000Z",
  "components": [
    {
      "name": "vpc/aws",
      "latest": "1.1.0",
      "fields": { "terraform": { "source": "registry.acme.dev/acme/vpc/aws" } },
      "versions": [
        {
          "version": "2.0.0",
          "digest": "sha256:9f...",
          "commit": "4c1e...",
          "time": "2026-10-03T00:00:00.000Z",
          "actor": "ci",
          "envs": ["registry"],
          "status": { "state": "yanked", "reason": "breaks routes", "replacement": "1.1.0", "actor": "ana", "time": "2026-10-05T00:00:00.000Z" },
          "changelog": { "bump": "major", "entries": [{ "kind": "breaking", "sha": "ab12...", "subject": "drop the ipv4 default" }] },
          "attestation": { "state": "signed", "verify": "cosign verify-blob --bundle vpc.bundle vpc.tgz", "identity": "ci@acme" },
          "consumers": [{ "repo": "acme/live", "root": "prod", "file": "prod/main.tf", "address": "module.vpc" }],
          "fields": {}
        }
      ]
    }
  ]
}
```

Components are sorted by name and versions are newest first. `latest` is the newest active version, by its version or by its digest when it has none, and `null` when no version is active. Readers ignore fields they do not know, and a field is only ever added within contract version 1.

## Static site

`renderCatalogSite(catalog, sections, { title })` returns the site's files, each with `path`, `contentType` and `bytes`, sorted by path:

| Path | Holds |
|---|---|
| `index.html` | Every component with its latest version, and a search box |
| `index.json` | The catalog itself, which the search box and `terragucci modules` read |
| `style.css`, `search.js` | The page style and the client-side search |
| `<component>/index.html` | The component's versions, and its engine sections |
| `<component>/<version>/index.html` | One version: status, digest, commit, attestation, changelog, consumers, engine sections |

A `/` in a component name becomes a directory, and any other character outside `A-Z a-z 0-9 . _ -` becomes `_`. The package `@acme/widgets` is therefore at `_acme/widgets/`. A release listed by digest `sha256:9f...` is at `sha256_9f.../` under its component. Every link is relative, so the site works under any prefix. The same catalog renders the same bytes, and a caller skips the files that did not change.

An engine adds its parts through `sections`. Both `sections.component(component)` and `sections.version(component, version)` return a list of `{ title, body }`. The body's `kind` is one of `text`, `code`, `table` or `html`, and a table carries its own columns and rows. Text and table cells are escaped. An `html` body is written as given, so only pass HTML the engine built itself.

A page of a deprecated or yanked version says so, with its reason, and links the replacement when the catalog lists it.
