# Composed roots demo

chant's own composed run over Terraform roots, as a tree a demo host can
drive. It is a stock chant project: three Terraform roots, `network`, `app`
and `edge`, each deployed by a `*.component.ts` with one `terraform-apply`
step, and `terraform.compose` on. It is the Terraform twin of
[`demo-composed-stacks`](../demo-composed-stacks), with the same two scenarios.

```
network  <-  app  <-  edge
```

Each root reads the one before it through variables. A component names the
edge twice: `dependsOn` orders the run, and a `stackOutput` in `vars` fills a
variable of the root from the other root's output of the same name. There is
no `terraform_remote_state`.

The base is a running set of roots, each with local state. network holds a
VPC, `aws_subnet.a` (10.0.1.0/24) and the SSM parameter `http-proxy-port`
(8080), and outputs `vpc_id`, `subnet_a_id` and `http_proxy_port`. app holds a
security group, a network interface in subnet a and the SSM parameter
`listener-port`, which takes the proxy port, and outputs `listener_port`. edge
holds the SSM parameters `allowlist` (`10.0.1.0/24`) and `upstream`
(`http://app:<listener_port>`). The roots run against an emulator: the AWS
provider takes its endpoint from `AWS_ENDPOINT_URL`. No scenario replaces or
deletes a resource.

## What runs where

`.forgejo/workflows/chant-pr.yml` is the pipeline chant generates for the
project, byte for byte:

```
chant build --components --generate forgejo --pr-loop --apply-on-merge --env demo \
  --image demo-chant-compose-roots:local --events-json \
  --report-url 's3://demo-reports/demo/chant/${{ github.repository }}'
```

On each pull request `chant components pr-plan` plans the roots the change
reaches and posts one note with one digest. With `terraform.compose` on, the
roots a change reaches that read each other form one group: chant writes a
root under `.chant-compose/` that calls each of them as a module, plans it
once, and cuts the plan back into each root's part. A value one root creates
is known after apply in the roots that read it. The apply plans the group
again under each root's state lock, applies only that same plan, and writes
each root's part of the state back. The report names the group under
`groups`, and each member's `groupOutcome`.

The pipeline was generated by the chant of the commit this directory was
added in (0.124.34 on the composed-runs branch), since composed runs
(chant#4419) are in no release yet. The job image carries chant, its
terraform lexicon and `tofu`.

`scenarios/` is the part of the tree the base does not get: the demo host
leaves it out of the base and overlays one scenario's `pull/` onto main for
its pull request. A scenario's `pull/` carries `*.component.ts` files of its
own, so the pipeline is generated from a copy of the tree without
`scenarios/`.

## The scenarios

Each has `about.json` (the kiosk's card), `pull/` (the pull request) and
`ask.json`, the prompts and replies the demo's prompt pane plays.

- `chant-compose-edit`: network's proxy port goes from 8080 to 8090 and it
  gains an `admin-port` of 9000. app adds `admin-listener-port`, and edge
  `admin-upstream`. The plan is 3 to create, 3 to change and 0 to delete, and
  every value is known at plan, since each port is a value of the source.
- `chant-compose-create`: network adds `aws_subnet.b` (10.0.2.0/24) and
  outputs `subnet_b_id`, unknown at plan. app adds `worker` in it, reading
  `subnet_b_id`, and outputs the worker's `subnet_id` as `worker_subnet_id`.
  edge records that id in the SSM parameter `worker-subnet`, and its
  `allowlist` becomes `10.0.2.0/24` too. The plan is 3 to create, 1 to change
  and 0 to delete. The subnet's id is known after apply in app and edge, and
  the one apply carries it to both.

## Tests

`lexicons/terraform/src/components/demo-composed-roots.e2e.test.ts` runs both
scenarios through `pr-plan`, one approval and `pr-apply`: on `tofu` with local
state against `CHANT_FLOCI_ENDPOINT`, and on `choudoufu` estates against
`CHOUDOUFU_EMULATOR_ENDPOINT`. For estates the test gives each root a `live`
block and reads each upstream through `terraform_estate_outputs`, keeping the
variables the components fill. Each run skips, with the reason, when its
binary or emulator is missing.
