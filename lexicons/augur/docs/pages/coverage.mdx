Not every kind chant knows about has an equivalent on an engine's side. This
page is the whole of what augur will and will not send, and it is generated
from `lexicons/augur/src/mapping.ts` — a table transcribed by hand is a table
that stops being true.

## Three states, not two

An entity type resolves to exactly one of three verdicts, and the second and
third are different answers rather than one answer written twice.

| Verdict | What it means | Where the entity lands |
|---|---|---|
| **Mapped** | augur sends it, as a kind, a provider, a region and a size | `entities`, with figures |
| **Declared unmapped** | augur has looked at this type and it carries no rate | `unpredicted`, reason `unsupported-kind`, detail naming the kind and the reason |
| **No row** | augur has never looked at this type | `unpredicted`, reason `unsupported-kind`, detail saying so and where to add the row |

The distinction between the last two is the point of writing the second table
down. "IAM roles are not priced, and here is why" is an answer a reader can act
on. "augur has never heard of this type" is a gap in `mapping.ts` and should be
filed as one. Collapsing them would leave a reader unable to tell a decision
from an omission — which is
[the observation contract](/chant/lexicon-authoring/observation-contract/)'s
"absent is not the same as unread", applied to prediction.

Neither road ends in a dropped entity or a zero. `behaviourReport` refuses a
report that leaves a name in neither map, so an entity that vanished is a
build failure rather than an estate that looks smaller than it is.

## Mapped

The size is read from the named property and sent **verbatim**. `t3.medium` and
`db.r6g.xlarge` are the provider's own vocabulary, which an engine's price model
is written against; parsing either into vCPU counts here would put a lossy hop
in front of a model that already knows the string. Where a declaration states no
size, the request carries none — a guessed size is a guessed price.

## Declared unmapped

Three families run through these reasons.

A **grant** is not a resource. An IAM role, an RBAC binding and a bucket policy
are statements about who may act; they have no rate, no capacity and no
behaviour under a lost zone.

A **boundary** is not a node. A VPC, a subnet and a namespace are where other
entities live. Sending them as nodes would draw a line from every resource to
its VPC and then price the drawing. Their real contribution to a prediction is
zone membership, which reaches the engine through
`edgeCoverage.containmentEdges` instead.

A **meter chant cannot read** is the honest one. A log group is priced by
ingested volume and a NAT gateway by an hourly rate plus everything that
crosses it. Both cost real money and neither number is in the declaration, so
the answer is `unsupported-kind` rather than a figure derived from half of it.

## Terraform resource blocks

Every `resource` block the terraform lexicon parses is `Terraform::Resource`
to chant, whatever provider type it declares, so a row on the entity type
alone would give a VPC and an instance the same verdict. augur looks a
terraform block up on its provider type instead, and reads its size from the
block's own arguments under `body`, in terraform's own vocabulary:
`instance_type`, not `InstanceType`. An argument that is still a reference,
`"${var.size}"`, is absent for the same reason a CloudFormation intrinsic is:
it names a value rather than being one.

A block carries no `type` field of its own, so the provider type is the
segment before the first dot of its address — `aws_subnet.app` is an
`aws_subnet` — taken only when that segment is shaped like a terraform type,
a provider name and an underscore. A resource the live path found in the
account and nothing declares has no terraform address at all; its identity
stands in for one, and it states its type on `resourceType`, the same field
ambient observation gives it.

These rows exist because a choudoufu root is a terraform root, and the live
path ([chant #2360](https://github.com/INTENTIUS/chant/issues/2360)) predicts
the account such a root holds. Without them every resource in that estate
was `provider-not-modelled` and the declared-versus-live delta was a
difference between two zeroes.

The substrate is the type's prefix. `aws_` has rows here. `google_` and
`azurerm_` are substrates augur does not model, `kubernetes_` is the
terraform provider rather than the k8s lexicon's own types, and `null_`,
`random_`, `local_` and `tls_` are utility providers with nothing in any
account; all of those are `provider-not-modelled`, naming the provider. An
`aws_` type with no row is `unknown-type`, the one verdict that is a gap.
The other block kinds a root declares, a `variable`, an `output`, a
`provider` configuration, are entity types of their own and sit in the
declared-unmapped table above.

## Adding a row

A type in neither table is a gap. Add it to `ENGINE_KINDS_BY_ENTITY_TYPE` with
its engine kind, or to `DECLARED_UNMAPPED` with a sentence saying what about it
has no rate; a terraform provider type goes in `ENGINE_KINDS_BY_TERRAFORM_TYPE`
or `DECLARED_UNMAPPED_TERRAFORM` in `mapping-terraform.ts`. `mapping.test.ts`
refuses a type in both halves, a kind outside the closed set, and a reason
short enough to be a shrug.
