`predictBehaviour()` is the fourth observation method, beside
`describeResources()`, `observeResourcesDeep()` and `listArtifacts()`. The other
three report what a substrate holds. This one reports what an engine believes
would happen at a level nobody has run, which is why it is named `predict` and
not `observe`.

The contract is
[`packages/core/src/behaviour.ts`](https://github.com/INTENTIUS/chant/blob/main/packages/core/src/behaviour.ts);
this page is what augur does inside it.

## Four moves, in this order

**Screen the request.** `screenBehaviourRequest` and nothing else. It walks the
whole request, `entities[*].props` included, and it is the only entry point:
calling `assertNoCredentialInOptions` instead applies one rule of three and
drops the other two.

**Resolve the engine.** Most specific first:

1. `CHANT_BEHAVIOUR_ENGINE_AUGUR`
2. `CHANT_BEHAVIOUR_ENGINE`
3. `BEHAVIOUR_ENGINE`

Nothing named is a refusal that names the variable to set. This happens before
anything is priced — a lexicon that prices first and checks the engine
afterwards has already decided what zero means.

**Build the request.** Offline and pure: no clock, no randomness, no
filesystem. Nodes and edges sorted, object keys sorted, the same input giving
the same bytes forever. The declared prediction and the live prediction are
meant to be shown as a delta, and a delta is only a statement about the estate
if both sides were assembled the same way.

**Ask, and translate.** One engine outcome onto the contract's builders. augur
computes no figures at all — there is no arithmetic on money anywhere in
`predict-behaviour.ts`, which is how "never a locally faked number" stays true
rather than being remembered.

## The screen runs first, and that ordering is load-bearing

With no engine configured *and* a credential in the request, `no-engine` would
be a correct-looking answer that hid the leak, and would keep hiding it until
somebody set the variable. So the screen comes first and the credential
refusal wins.

The two arms differ in blast radius on purpose. A value that **is** a
credential throws, which fails the whole lexicon: a live token bound for a
third party is a stop, not a degradation. A merely suspicious *field name*
returns a refusal, because that arm is a heuristic and an earlier version of it
took a whole overlay down over one `tags: { author: "…" }`.

The guard is a denylist of known formats with no entropy scoring. It walks
build output full of ARNs, digests and resource ids, and a heuristic that
refused those would refuse real projects rather than protect them. A novel
issuer's format or a bare random string passes.

## Reaching the engine

The address may be a URL or a command on PATH, and the transport that carries
the request is the contract's, not augur's: `BehaviourTransport` in
`packages/core/src/behaviour.ts` takes the rendered request and brings back the
engine's text or a finished refusal. augur renders, sends, and parses what
comes back; it never sees a byte of the wire itself.

A **URL** goes to core's HTTP transport. The request is `POST`ed as JSON with a
bearer token, and the token is read from its own chain, most specific first:

1. `CHANT_BEHAVIOUR_TOKEN_AUGUR`
2. `CHANT_BEHAVIOUR_TOKEN`
3. `BEHAVIOUR_TOKEN`

That is a second chain rather than the address chain reused, because an address
is printed in refusals and a token never is. With a URL named and no token set,
augur refuses by name before sending anything. The token goes in the
`authorization` header and nowhere else: it is not in the request body, which
the credential screen has already walked, and it is not in any refusal, even
when the engine echoes it back into an error page.

A **command on PATH** is spawned by augur's own transport: the request goes to
the command's stdin as canonical JSON and the answer comes back on stdout, with
no shell in between. The child is given an environment holding `PATH` and
nothing else. Rule 3 is that the engine never sees a credential, and a
subprocess inheriting `process.env` walks straight around the request-side
screen — the request would be spotless and the child would hold the whole
environment anyway.

Any other scheme is refused as unreachable, naming the address.

## What each refusal means

| Cause | What happened | What to do |
|---|---|---|
| `no-engine` | No variable in the chain named one; or a URL was named and no variable holds a token, or the engine rejected the token it holds | Set `CHANT_BEHAVIOUR_ENGINE`, or `CHANT_BEHAVIOUR_TOKEN` — the reason says which |
| `engine-unreachable` | An address was named and did not answer: connection refused, a timeout, a `5xx`, a redirect, or an answer that is not the wire format | Check the address, or repoint the variable |
| `engine-out-of-credit` | The engine answered `402`, or said so in the body of an otherwise-`200` answer: the account behind the token has no balance | Pay. Waiting never fixes it |
| `engine-over-quota` | The engine answered `429`, or said so in the body: a limit is spent | Usually wait for the window; paying does nothing |
| `credential-in-request` | The request carried something that must not leave the process | Remove it, or hold it in a reference the build does not expand |

Some engines answer `200` and put the refusal in the envelope, and a command
engine has no status at all, so the body's own words pick the cause when the
status did not. They are read only on an answer that failed to parse: a report
that priced the estate and declined one node "rate limit reached for this
region" is still a report, not an over-quota refusal about nothing.

Four causes rather than one, because a refusal exists to be acted on and each
of these wants a different action. Reporting a spent quota as unreachable sends
an operator to debug a network that is answering perfectly well. The mapping
from what the wire said to which cause is written once, in the contract's
transport, so no lexicon can fold one into another.

A refusal carries **no** `entities` map and **no** `meta`, empty or otherwise.
"The engine is gone" and "the estate costs nothing" are different objects, and
no amount of downstream carelessness can turn the first into the second.

## Coverage, stated rather than assumed

Two claims travel with every request, and both exist because the alternative is
a confident wrong answer.

`edgeCoverage` says how complete the edge list is. An empty edge list cannot
distinguish "nothing references anything" from "I could not work out what
references what", and containment — a subnet inside a VPC — is deliberately not
an edge, so zone membership is absent by design. An engine asked whether an
estate survives one zone lost, over a graph carrying no zone membership,
answers confidently and wrongly.

`withheld` says which entities were not sent, and why, from
[the coverage table](../coverage/). Same argument one level along: an engine
handed twelve nodes cannot tell whether the estate has twelve or twenty.

## On a pull request

The prediction reaches a review as a finding through core's `BehaviourOp`
composite ([chant #2358](https://github.com/INTENTIUS/chant/issues/2358)).
The example project declares one in `src/pr-behaviour.op.ts`:

```typescript
import { BehaviourOp } from "@intentius/chant/op";

const { op } = BehaviourOp({
  name: "pr-behaviour",
  env: "dev",
  traffic: "1000 rps, p99",
});

export default op;
```

The Op predicts the declared estate twice, on the pull request's head and on
the base branch it targets, and posts the delta as one sticky comment on the
pull request (GitHub, Forgejo) or one note on the merge request (GitLab). The
trigger is `{ kind: "pull_request" }` on the `ScheduledOpSpec` handed to
`generateOpsPipeline`, with `findingMode: "comment"`; there is no schedule,
because the pull request is the cadence.

What the finding shows follows from this page. An entity the coverage table
withholds — the Op itself, the two profiles, every VPC and subnet — is
declined by name on both sides and appears as a row saying so, never as a zero
and never as a cost change. A pair whose provenance or traffic level differs
between the two sides is marked with every mismatching axis and is not
subtracted. Each side's edge coverage is shown, and because the declared path
never claims `complete` — it has references and no containment — the two
resilience verdicts are shown per side rather than compared. A run with no
engine configured posts a finding that says "no prediction" and carries the
refusal from the table above, remedy included.

`chant run pr-behaviour` on a developer's machine needs the base branch named
by hand and no forge to post to: `BehaviourOp({ …, base: "main",
findingMode: "report" })` returns the body instead.

## What is not here

augur declares no `describeResources`, no `observeResourcesDeep` and no
`listArtifacts`. That is the shape rather than a gap — augur has no substrate to
read. Declaring one that returned an empty list would pass a check while
claiming a read that never happens.
