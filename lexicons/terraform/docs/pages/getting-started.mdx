Most chant lexicons ask you to declare infrastructure in TypeScript. This one
starts from the `.tf` files you already have. You name the root modules, chant
parses them, and the blocks join the build as entities that the post-synth
checks can read. Nothing is written back over the HCL.

## Install

```bash
npm install --save-dev @intentius/chant-lexicon-terraform
```

## Name your roots

Add the `terraform` namespace to `chant.config.ts`. Importing the package is
what brings the key into `ChantConfig`.

```ts
import type { ChantConfig } from "@intentius/chant/config";
import "@intentius/chant-lexicon-terraform";

export default {
  lexicons: ["terraform"],
  terraform: {
    binary: "terraform",
    roots: {
      app: { dir: "./terraform" },
    },
  },
} satisfies ChantConfig;
```

`dir` resolves against the project root, the directory holding
`chant.config.ts`, because a `.tf` tree usually sits beside the typed source
rather than inside it. Each root also takes an optional `workspace`, a
`varFiles` list and a `backendConfig` map.

`binary` is `"terraform"` or `"tofu"`. The two are wire-compatible for
everything this lexicon does, so the choice is recorded rather than guessed.

The binary also says which files of a root are its configuration, as it does
for the binary itself. Under `"terraform"` (and when `binary` is unset) a root
is its `.tf` and `.tf.json` files. Under `"tofu"` or `"choudoufu"` its `.tofu`
and `.tofu.json` files count too, and `x.tofu` replaces `x.tf` when both
exist, which is OpenTofu's own rule. The parse, change detection, the backend
and state readers and the pin rollout all read that one set.

The other keys of the namespace:

| Key | Default | What it sets |
|---|---|---|
| `callModuleType` | `"local"` | How far a root's parse follows its `module` calls: `local`, `none`, or `all` (refused). |
| `moduleRoot` | the project root | The directory local module sources may resolve within. |
| `observe` | `"state"` | How deep each root is observed: `state` or `plan`. |
| `compose` | off | Composed runs: `{ enabled: boolean, max?: number }`, `max` default 10. |

With `compose.enabled`, the `terraform-apply` components a pull request
reaches that read each other plan as one plan and apply as one apply. A
group with a member that cannot compose plans root by root as before, and
the report says why. See [In a composed run](/chant/lexicons/terraform/ops/#in-a-composed-run).

## Build

```bash
chant build
```

Every block of every configured root becomes one entity, keyed
`<root>/<address>`:

| HCL | Entity type | Key |
|---|---|---|
| `terraform { ... }` | `Terraform::Terraform` | `app/terraform` |
| `provider "null" {}` | `Terraform::Provider` | `app/provider.null` |
| `resource "null_resource" "web" {}` | `Terraform::Resource` | `app/null_resource.web` |
| `data "aws_ami" "base" {}` | `Terraform::Data` | `app/data.aws_ami.base` |
| `module "cdn" {}` | `Terraform::Module` | `app/module.cdn` |
| `variable "region" {}` | `Terraform::Variable` | `app/var.region` |
| `output "url" {}` | `Terraform::Output` | `app/output.url` |
| `locals { ... }` | `Terraform::Locals` | `app/locals` |

Each entity carries `props.address`, `props.body` (the block, verbatim from the
parser), `props.file` and `props.root`.

The build writes no Terraform of its own. `terraform apply` keeps working on
your `.tf` files as before.

## Graph the estate

```bash
chant graph --format ir
```

Every parsed block is a node, and every reference between two blocks is an
edge. Five reference forms become edges: `resource`, `data`, `module`, `var`
and `local`. `depends_on` is one too, with no attribute on it.

Each edge names the attribute it flows through on both sides, the way
[`chant graph`](/chant/cli/graph/) labels any other reference. A
`subnet_id = aws_subnet.private.id` gives `viaAttr: "subnet_id"` and
`toAttr: "id"`; an edge whose reference named two producer attributes carries
no `toAttr` rather than an arbitrary one.

A `count` or `for_each` block stays one node. chant's entity is the block, not
the instance, so `count = 3` draws one card and one edge per target, and the
block records which meta-argument expanded it on `props.expansion`. The
instance count is known only at plan time, and this reads the declaration.

References resolve inside their own module scope, which is Terraform's own
namespace: a `var.region` inside `module.cdn` is the child module's variable
and never the root's. Nothing resolves across roots.
Separate roots read each other by name through a data source, not by
reference.

`groups.byStack` is keyed by root name, one entry per root you named in
`terraform.roots`. That is the grouping a boundary-box renderer draws, and a
root is what one `terraform apply` runs against. `groups.byLexicon` keeps
saying `terraform`.

A `provider = aws.replica` meta-argument is not an edge. It names a provider
block by type and alias together, and the entity key for one is
`provider.<type>` with the alias inside the body, so two aliased providers of
the same type cannot be told apart from the reference.

## What the checks tell you

`TF001` fires once per root whose `terraform` block declares neither a
`backend "<type>"` nor a `cloud {}`, and once per root whose only backend is
`backend "local"`. Such a root keeps its state in a local `terraform.tfstate`:
unshared, unlocked, and holding every resource attribute in plaintext. The
first apply from a second machine starts from an empty state and proposes to
create the estate again.

Add a remote backend to clear it:

```hcl
terraform {
  backend "s3" {
    bucket = "acme-tfstate"
    key    = "app/terraform.tfstate"
    region = "us-east-1"
  }
}
```

## Failure modes

A root whose `dir` does not exist, or one holding a `.tf` the parser refuses,
produces a warning naming the root and contributes no entities. The rest of the
build carries on, and the other roots are unaffected. Reading someone else's
estate is the job here, so half of it parsing is more useful than none of it.

## Driving the root: TerraformApplyOp on the local executor

The build only reads the root's blocks. To run init, plan and apply on it,
declare a `TerraformApplyOp` and run it with `chant run`:

```typescript
import { TerraformApplyOp } from "@intentius/chant-lexicon-terraform";

export const { op } = TerraformApplyOp({
  name: "app-apply",
  root: "app",
  gate: "never", // no approval step, so a run goes straight through, see below
});
```

`gate: "never"` matters here specifically: every other gate mode emits a Gate
phase, and a run that reaches a gate nobody has approved records a pending fact
on the gate ledger, ends with status `gated` and exits 3, so Apply never runs
until someone records the resolution with `chant approve`. With it, `chant run
app-apply` executes Init, Plan and Apply straight through in your terminal. See
[Ops](../ops/) for every `TerraformApplyOp` option, the four activities and
builders underneath it, and the compensation rule for a failed apply.

## A root as a workspace member

A root can also be a member of a [chant workspace](/chant/reference/workspace-declaration/)
without a chant project of its own. This lexicon supplies the `terraform` member
kind as data, in `workspace-kinds.json` at its `./workspace-kinds` subpath. Pin
the lexicon in `chant.workspace.json` and declare the root with that kind.

```json
{
  "name": "estate",
  "schema": 1,
  "pins": [{ "package": "@intentius/chant-lexicon-terraform", "version": "0.80.0" }],
  "members": [{ "name": "network", "dir": "network", "kind": "terraform" }]
}
```

The kind's probe passes when a `.tf` file sits directly in the member's
directory, and its precedence is 400. A chant project (500) that keeps `.tf`
files beside its config is still a `chant` member. A choudoufu root passes this
probe too, and the `choudoufu` kind this lexicon also ships (450, an
`estate.chdf.hcl` sidecar or a `live` block) outranks it. `chant workspace ls` reads the kind from the file and never
imports the lexicon. behold's own `terraform` member kind moved here, so an estate
behold reads lists the same way in a chant workspace. See
[Workspace Kinds](/chant/reference/workspace-kinds/#terraform-and-choudoufu) for the
format.
