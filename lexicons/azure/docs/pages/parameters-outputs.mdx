## Parameters

Use `CoreParameter` from the core package to define ARM template parameters. These become `parameters` in the output JSON.

```typescript
import { CoreParameter } from "@intentius/chant";

export const environment = new CoreParameter({
  name: "environment",
  type: "string",
  default: "dev",
  allowedValues: ["dev", "staging", "production"],
});

export const location = new CoreParameter({
  name: "location",
  type: "string",
  default: "[resourceGroup().location]",
});

export const nodeCount = new CoreParameter({
  name: "nodeCount",
  type: "int",
  default: 3,
});
```

A resource's attributes are `AttrRef`s for the same `reference()` call. A dotted attribute reads a nested field, with dots written as underscores: a Container App's `configuration.ingress.fqdn` is `app.configuration_ingress_fqdn`, and its `latestRevisionFqdn` is `app.latestRevisionFqdn`. ARM schemas don't mark read-only fields, so the lexicon keeps a curated list per resource type, and a type that isn't on it has only `id`.

### Generated ARM output

```json
{
  "parameters": {
    "environment": {
      "type": "string",
      "defaultValue": "dev",
      "allowedValues": ["dev", "staging", "production"]
    },
    "location": {
      "type": "string",
      "defaultValue": "[resourceGroup().location]"
    },
    "nodeCount": {
      "type": "int",
      "defaultValue": 3
    }
  }
}
```

### Referencing parameters

Parameters are referenced via ARM bracket expressions:

```typescript
export const storage = new StorageAccount({
  name: "[parameters('storageName')]",
  location: "[parameters('location')]",
});
```

## Outputs

Use `StackOutput` from the core package to define ARM template outputs.

```typescript
import { StackOutput } from "@intentius/chant";
import { Reference } from "@intentius/chant-lexicon-azure";

export const storageEndpoint = new StackOutput({
  name: "storageEndpoint",
  value: Reference("myStorage").primaryEndpoints.blob,
});

export const storageId = new StackOutput({
  name: "storageAccountId",
  value: "[resourceId('Microsoft.Storage/storageAccounts', 'myStorage')]",
});
```

### Generated ARM output

```json
{
  "outputs": {
    "storageEndpoint": {
      "type": "string",
      "value": "[reference('myStorage').primaryEndpoints.blob]"
    },
    "storageAccountId": {
      "type": "string",
      "value": "[resourceId('Microsoft.Storage/storageAccounts', 'myStorage')]"
    }
  }
}
```

## Parameter types

ARM supports these parameter types, mapped from `CoreParameter`:

| CoreParameter type | ARM type | Notes |
|-------------------|----------|-------|
| `"string"` | `string` | Most common |
| `"int"` | `int` | Integer values |
| `"bool"` | `bool` | Boolean values |
| `"array"` | `array` | JSON arrays |
| `"object"` | `object` | JSON objects |
| `"secureString"` | `secureString` | Passwords, keys (not logged) |
| `"secureObject"` | `secureObject` | Sensitive objects |

## Outputs that aren't attributes

`output()` also takes a literal or an azure intrinsic. A string, an integer or a boolean is written with its ARM type, and an intrinsic such as `ResourceId(...)` is written as its `[...]` expression. A literal or intrinsic output has no resource behind it, so every lexicon in the build receives it; a CloudFormation intrinsic is left to the aws template. Anything else is not written, and the build prints a warning that names the output.
