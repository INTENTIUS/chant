## Resource types

Every Azure resource has a **type** in the format `Microsoft.{Provider}/{ResourceType}`. The lexicon generates a TypeScript class for each type.

```typescript
import { StorageAccount, VirtualMachine, WebApp } from "@intentius/chant-lexicon-azure";
```

Common resource types:

| Type | Class | Description |
|------|-------|-------------|
| `Microsoft.Storage/storageAccounts` | `StorageAccount` | Blob, file, queue, table storage |
| `Microsoft.Compute/virtualMachines` | `VirtualMachine` | IaaS virtual machines |
| `Microsoft.Web/sites` | `WebApp` | App Service web applications |
| `Microsoft.Web/serverfarms` | `AppServicePlan` | App Service plans |
| `Microsoft.Network/virtualNetworks` | `VirtualNetwork` | Virtual networks |
| `Microsoft.Network/networkSecurityGroups` | `NetworkSecurityGroup` | Firewall rules |
| `Microsoft.ContainerService/managedClusters` | `ManagedCluster` | AKS Kubernetes clusters |
| `Microsoft.KeyVault/vaults` | `KeyVault` | Secret and key management |
| `Microsoft.Sql/servers` | `SqlServer` | Azure SQL logical servers |
| `Microsoft.ContainerRegistry/registries` | `ContainerRegistry` | Docker container registries |

## Resource-level fields

ARM templates have fields that sit at the resource level (outside `properties`):

### sku
The pricing tier or capability level:
```typescript
export const storage = new StorageAccount({
  sku: { name: "Standard_GRS" },
});
```

### kind
Disambiguates resource subtypes:
```typescript
export const storage = new StorageAccount({
  kind: "StorageV2", // or "BlobStorage", "BlockBlobStorage"
});
```

### identity
Managed identity configuration:
```typescript
export const app = new WebApp({
  identity: { type: "SystemAssigned" },
});
```

### tags
Key-value metadata:
```typescript
export const storage = new StorageAccount({
  tags: { environment: "production", team: "platform" },
});
```

### zones
Availability zone placement:
```typescript
export const vm = new VirtualMachine({
  zones: ["1"],
});
```

### plan
Marketplace plan information:
```typescript
export const vm = new VirtualMachine({
  plan: {
    name: "my-plan",
    publisher: "my-publisher",
    product: "my-product",
  },
});
```

### location
Azure region. Defaults to `[resourceGroup().location]`:
```typescript
import { Azure } from "@intentius/chant-lexicon-azure";

export const storage = new StorageAccount({
  location: Azure.ResourceGroupLocation, // default
  // or: location: "eastus2",
});
```

## properties

Everything that isn't a resource-level field goes under the template's `properties`. Pass the fields flat, or pass ARM's own `properties` object as the generated types describe it; either way the template has one `properties` level.

## Names and references

A resource's `name` prop is its ARM name, and the export name stands in only when there is no `name`. A reference to another resource uses the ARM name: `.id` becomes `[resourceId('<type>', '<name>')]`, any other attribute becomes `[reference('<name>').<attribute>]`, and `dependsOn` is inferred from both. A child resource named `vnet/apps` gets one `resourceId` argument per segment.

## apiVersion

Every ARM resource requires an `apiVersion`. The serializer fills in the latest stable version, so you rarely set it.

The post-synth checks AZR011 and AZR012 validate:
- **AZR011**: apiVersion exists and follows YYYY-MM-DD format
- **AZR012**: apiVersion is not outdated (older than 2023-01-01)
