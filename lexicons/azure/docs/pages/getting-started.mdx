## What is chant?

chant compiles TypeScript declarations into ARM template JSON.

## Install

```bash
npm install --save-dev @intentius/chant @intentius/chant-lexicon-azure
```

## Your first ARM template

The fastest path is the **StorageAccountSecure** composite, one call that returns a configured storage account:

```typescript
// src/main.ts
import { StorageAccountSecure } from "@intentius/chant-lexicon-azure";

const { storageAccount } = StorageAccountSecure({
  name: "myappstorage01",
  sku: "Standard_LRS",
  tags: { environment: "dev" },
});

export { storageAccount };
```

Build and deploy:

```bash
# Generate ARM template JSON
chant build --output dist/template.json

# Validate with Azure CLI (no changes applied)
az deployment group validate \
  --resource-group my-rg \
  --template-file dist/template.json

# Deploy for real
az deployment group create \
  --resource-group my-rg \
  --template-file dist/template.json
```

## Using resource constructors

You can also call the resource constructors directly:

```typescript
import { StorageAccount, Azure } from "@intentius/chant-lexicon-azure";

export const storage = new StorageAccount({
  name: "mystorageaccount",
  location: Azure.ResourceGroupLocation,
  kind: "StorageV2",
  sku: { name: "Standard_LRS" },
  supportsHttpsTrafficOnly: true,
  minimumTlsVersion: "TLS1_2",
});
```

## Default tags

Apply tags to every taggable resource in your project:

```typescript
// src/tags.ts
import { defaultTags } from "@intentius/chant-lexicon-azure";

export const tags = defaultTags([
  { key: "Project", value: "my-app" },
  { key: "Environment", value: "dev" },
  { key: "ManagedBy", value: "chant" },
]);
```

## Init templates

Start a new project with a template:

```bash
# Default — basic storage account
chant init --lexicon azure

# Web app — App Service with managed identity
chant init --lexicon azure --template web-app

# AKS cluster — Kubernetes with VNet and ACR
chant init --lexicon azure --template aks-cluster
```

## In a composed run

An `arm-deploy` step is a hole in a composed run ([ws-108](https://github.com/INTENTIUS/chant/blob/main/docs/design/decisions/ws-108-how-each-lexicon-composes.md)). When its input reads another component's output that has no value yet, the plan reads nothing and the member's hole says `inputs from <component>; re-checked on apply`. After the upstream applies, that round needs its own approval. The step takes no template parameters, so an upstream value can only name the target. chant applies each resource with its own PUT and makes no ARM deployment, so ARM what-if has nothing to preview.
