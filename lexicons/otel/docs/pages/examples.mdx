Each example lives under `lexicons/otel/examples/` and builds with `chant build src --lexicon otel`. The lexicon's tests build every one, lint it with no warnings, and check the emitted config with `validateCollectorConfig`.

## getting-started

OTLP in on gRPC and HTTP, `memory_limiter` then `batch`, traces to `otlp/tempo` and logs to `debug`, with a `health_check` extension.

{{file:getting-started/src/collector.ts|title=src/collector.ts}}

## k8s-node-agent

A per-node agent config: `hostmetrics`, container logs through `filelog`, OTLP from pods, `k8sattributes`, `resourcedetection`, `resource` and `attributes` processors, metrics served for Prometheus and traces and logs sent to a gateway. The files are split by concern, and a `Service` fixes extension start order and sets collector telemetry.

{{file:k8s-node-agent/src/pipelines.ts|title=src/pipelines.ts}}

## genai-agent

The [GenAI preset](../genai-pipeline/) for an agent service: content removed, values that look like card numbers masked, span and token metrics served for Prometheus, and traces sent to Tempo.

{{file:genai-agent/src/collector.ts|title=src/collector.ts}}

## tail-sampling-gateway

A gateway tier: every span becomes `spanmetrics` metrics first, then a `forward` connector hands the spans to a `traces/sampled` pipeline whose `tail_sampling` keeps errors, traces of 500ms or more and a 10% baseline, and sends them to Tempo. Split into components, sampling and pipelines.

{{file:tail-sampling-gateway/src/pipelines.ts|title=src/pipelines.ts}}

## custom-component

A Splunk HEC exporter defined with `defineComponent`, with a schema pin and its own validation, used next to built-ins. See [Custom components](../custom-components/).
