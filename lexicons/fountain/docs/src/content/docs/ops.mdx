Two op activities ship with the lexicon, resolvable by name via `loadActivities(["fountain"])`.

## fountainApply

The native applier: compiles the serializer's manifest YAML into fountain's bulk `POST /api/apply` request and sends it in one call.

| Behavior | Detail |
|---|---|
| Create / update | By name, reconciled server-side. An agent's `environment` reference resolves by name — against the manifest or the tenant's existing environments — without a client-side id lookup. |
| Order | Environment → Vault → Agent, fixed server-side regardless of manifest order. |
| Prune | Off by default. With `prune: true`, chant-owned resources absent from the manifest are deleted, in reverse order — the one thing bulk apply doesn't cover, so this still lists live state per kind. |
| Secrets | `spec.secrets` converts from chant's authored `{key, value}[]` to the wire's `{KEY: value}` map; the server upserts them through the encrypted envelope path in the same request. Upsert-always — values are write-only upstream. |
| Failure | Best-effort per resource. Every result is collected before this throws, so one bad resource doesn't hide failures elsewhere in the manifest. |

```typescript
await fountainApply({ manifestPath: "build/fountain.yaml", prune: true });
```

Endpoint and token resolution: explicit args win, then the named `fountain.profiles` entry (`profile` arg, falling back to `defaultProfile`), then `FOUNTAIN_ENDPOINT` / `FOUNTAIN_TOKEN`, then the hosted default. See [Profiles](/chant/lexicons/fountain/profiles/).

## fountainRun

Conversations are runs, not resources, so they are started rather than declared. `fountainRun` resolves the agent by name, starts a conversation (optionally with a prompt and an allowlisted vault), and polls until the launch is done. What counts as done depends on the agent's `sandbox_mode` and on whether the launch has a prompt.

| Launch | Done when | `status` in the result |
|---|---|---|
| Ephemeral agent | The conversation reaches `completed`, `failed`, `timed_out` or `terminated`. | The conversation's status. |
| Persistent agent, with a prompt | The conversation settles on `idle` (or one of the above). | The turn's own outcome: `completed`, `failed` or `interrupted`. |
| Persistent agent, no prompt | The conversation's sandbox is `ready` or `failed` and no turn is running. fountain v0.21.0 leaves such a conversation `pending`, since no turn starts. | `provisioned`, or `failed` with `failedStage` naming the provisioning stage that failed. |

An empty `prompt` counts as no prompt. The result also carries `sandboxId` and `spriteName` (fountain's `sandbox.sprite_name`), so a caller can reach the machine without listing `/api/sandboxes`. `spriteName` in the args passes through as fountain's `sprite_name`, the suffix of the machine's name, so a box's runtime can predict it.

| Arg | Effect |
|---|---|
| `timeoutMs` | Deadline for the wait. Default 10 minutes. |
| `pollMs` | Poll interval. Default 5 seconds. |
| `sandboxApiAccess` | fountain's `sandbox_api_access`. `owner`, fountain's default, gives the sandbox a callback token (`FOUNTAIN_TOKEN`) scoped to the owner. `none` gives it none. fountain v0.21.0 accepts `none` only for a fresh ephemeral sandbox, so `fountainRun` refuses it for a persistent agent before starting anything ([managoat/fountain#2497](https://github.com/managoat/fountain/issues/2497)). |
| `terminate` | What happens to the conversation's machine when the wait ends: `on-deadline` (the ephemeral default) terminates only a run whose turn never ended, `never` (the persistent default) leaves it, `always` terminates it either way. |

Under `chant run` the executor calls both activities as `fn(args, signal)`. When the signal fires (the step's timeout, or Ctrl-C) `fountainRun` stops polling, applies the `terminate` policy as it does at its deadline, and the step fails.

```typescript
phase("Start", [activity("fountainRun", { agent: "studio-box", spriteName: "studio-box" })]);
```

Multi-turn interaction, meaning follow-up prompts and interrupts, is fountain's own conversations API. The lexicon stays at the lifecycle edges.
